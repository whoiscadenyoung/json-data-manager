# Dataset Overview tab, standalone groups & many-to-many collections

## Model (per your answers)
- **Collections: many-to-many** — a dataset can belong to any number of collections, via a new join table. Collections become pure labels/containers; no implied hierarchy.
- **Groups: 0–1 per dataset** (unchanged cardinality), and groups can now exist **standalone** (no parent collection).
- Group membership and collection memberships are **independent** — adding a dataset to a group no longer touches its collections, and vice versa.
- **No data migration** — dev data gets wiped and you re-import funding sources after.

## Phase 1 — Backend: `packages/json-cms` component
1. **`src/component/schema.ts`**:
   - `groups.collectionId` → `v.optional(v.id("collections"))`.
   - **New table** `schemaCollections`: `{ schemaId: v.id("schemas"), collectionId: v.id("collections") }` with `.index("by_schema", …)` and `.index("by_collection", …)`.
   - `schemas`: remove `collectionId` + its `by_collection` index (`groupId`/`by_group` stay).
2. **`src/component/lib.ts`**:
   - New `addSchemaToCollection` (idempotent) / `removeSchemaFromCollection` replace `setSchemaCollection`; new query `listCollectionsBySchema`; new query `listSchemaCollections` (all join rows, for counts/candidate filtering).
   - `listSchemasByCollection` + `listGeospatialSchemaIdsByCollection` (feeds `listEntriesByCollection`): resolve via join table.
   - `setSchemaGroup`: sets/clears `groupId` only — no collection side effects.
   - `createGroup`: `collectionId` optional; `listGroups`: `collectionId` optional → all groups when omitted.
   - `deleteCollection`: delete join rows for this collection + delete its nested groups (clearing `groupId` on their datasets); other memberships of surviving datasets untouched.
   - `deleteSchema`: also delete its `schemaCollections` rows.
3. **`src/client/index.ts` (`exposeApi`)**: mirror the arg/surface changes (optional `collectionId` on createGroup/listGroups; new add/remove/list functions; drop `setSchemaCollection`).
4. **Tests (`src/component/lib.test.ts`)** — no group/collection tests exist today; add a block covering: standalone `createGroup`; `listGroups` all vs by-collection; add/remove collection (idempotent, multi-collection); `listSchemasByCollection`/`listCollectionsBySchema`; `setSchemaGroup` independence; `deleteCollection` partial cascade; `deleteSchema` join cleanup.
5. Rebuild: `cd packages/json-cms && bun run build:codegen`.
