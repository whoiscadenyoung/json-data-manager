2026-11-10, #301 (editor at `app/src/features/views`, store reads in
`lib/store/view-reads.ts`, migration `0028_retire_derived.sql`).

- **Column pickers and previews for unpublished project drafts work because
  they read `view_input_meta` (invoker RPC, RLS only, NO lifecycle gate) and
  the server preview takes the draft DEFINITION.** Do not source picker titles
  or fields from `datasets.listSummariesQueryOptions` (it filters
  `lifecycle = published`) or you re-create the #281 bug (raw UUID, no
  pickers). Titles come back as `null` when RLS hides an input.
- **PostgREST embed `view_inputs` needs the FK hint** (`view_inputs!view_id(...)`):
  the table references `datasets` twice (view and input), so a bare embed is
  ambiguous.
- **base-ui `Select.Value` renders the raw `value`** (a dataset uuid in a
  dataset picker). Always render the label as the child; `LabeledSelect`
  (features/views/components) does it.
- **A step list edit that leaves an input unread** would declare a dead input;
  Save runs `prunedInputs` (keeps the base). `view_inputs` is rewritten on
  every save.
- **`routeTree.gen.ts` is only regenerated by the vite plugin**: start
  `bunx vite dev` once after adding a route file (there is no tsr CLI
  installed). tsc fails on the new `to:` until you do.
- **Narrowing `ProjectArtifactRow.artifactKind` to the real DB domain**
  (`dataset | layer | app`) was what surfaced every dead `"derived"` branch;
  keep it narrow.
- **What retired:** `derived_datasets`, the `derived` artifact kind, the
  "Join into a table" mint (it was client code over the registry, never an
  RPC), `lib/store/derived.ts`, the derived route/page, the Transform tab,
  `pg-transform-*`, the lookup/rollup executors in `data-core/transform`
  (only the `sql` engine stays for the Analysis tab until #306), the derived
  read paths in `dataset-rows(-pg).ts`, "include joined fields" in exports,
  and the Convex-era `publish.ts` / `bundle-publish.ts` / `AnalysisPanel` /
  `DatasetOverview` / `dataset-consumption` that only existed for them.
  The Analysis tab lost its saved analyses (it saved them AS derived
  datasets): it is an unsaved scratch pad now.
- **Left on purpose:** `app/convex/**` (archived Convex backend, untouched),
  `map-layers.ts`' derived re-key helpers (fed `NO_RENDERABLE_DERIVED`
  empties; remove with the Convex map seam), and `publish_bundle_members.kind`
  / `consumer_references.consumer_kind` still allow `'derived'` in their CHECKs.
- Datasets a view reads cannot be deleted (NO ACTION FK): `datasetsStore.remove`
  pre-checks `view_inputs` and throws `DatasetInUseError` naming the views.
