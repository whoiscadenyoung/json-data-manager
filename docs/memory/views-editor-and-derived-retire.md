2026-11-10, #301 (editor at `app/src/features/views`, store reads in
`lib/store/view-reads.ts`, migration `0028_retire_derived.sql`).

- **Column pickers and previews for unpublished project drafts work because
  they read `view_input_meta` (invoker RPC, RLS only, NO lifecycle gate) and
  the server preview takes the draft DEFINITION.** Do not source picker titles
  or fields from `datasets.listSummariesQueryOptions` (it filters
  `lifecycle = published`) or you re-create the #281 bug (raw UUID, no
  pickers). Titles come back as `null` when RLS hides an input.
- **PostgREST embed `view_inputs` needs the FK hint** (`view_inputs!view_id(...)`):
  the table references `datasets` twice (view and input), so a bare embed is
  ambiguous.
- **base-ui `Select.Value` renders the raw `value`** (a dataset uuid in a
  dataset picker). Always render the label as the child; `LabeledSelect`
  (features/views/components) does it.
- **A step list edit that leaves an input unread** would declare a dead input;
  Save runs `prunedInputs` (keeps the base). `view_inputs` is rewritten on
  every save.
- **`routeTree.gen.ts` is only regenerated by the vite plugin**: start
  `bunx vite dev` once after adding a route file (there is no tsr CLI
  installed). tsc fails on the new `to:` until you do.
- **Narrowing `ProjectArtifactRow.artifactKind` to the real DB domain**
  (`dataset | layer | app`) was what surfaced every dead `"derived"` branch;
  keep it narrow.
- **What retired:** `derived_datasets`, the `derived` artifact kind, the
  "Join into a table" mint (it was client code over the registry, never an
  RPC), `lib/store/derived.ts`, the derived route/page, the Transform tab,
  `pg-transform-*`, the lookup/rollup executors in `data-core/transform`
  (only the `sql` engine stays for the Analysis tab until #306), the derived
  read paths in `dataset-rows(-pg).ts`, "include joined fields" in exports,
  and the Convex-era `publish.ts` / `bundle-publish.ts` / `AnalysisPanel` /
  `DatasetOverview` / `dataset-consumption` that only existed for them.
  The Analysis tab lost its saved analyses (it saved them AS derived
  datasets): it is an unsaved scratch pad now.
- **Left on purpose:** `app/convex/**` (archived Convex backend, untouched),
  `map-layers.ts`' derived re-key helpers (fed `NO_RENDERABLE_DERIVED`
  empties; remove with the Convex map seam), and `publish_bundle_members.kind`
  / `consumer_references.consumer_kind` still allow `'derived'` in their CHECKs.
- Datasets a view reads cannot be deleted (NO ACTION FK): `datasetsStore.remove`
  pre-checks `view_inputs` and throws `DatasetInUseError` naming the views.

## #302 advanced steps (editor half)

- **One recursive `StepList`** (`features/views/components/step-list.tsx`)
  renders the top level AND every join's `right.steps`; nested cards find their
  diagnostics and validation errors by `path` (`steps[0].right.steps[1]`).
  A sub-pipeline step's diagnostics `index` is LOCAL to its list, so
  `stepDiagnosticsOf(payload, index)` matches only entries WITHOUT a `path`;
  nested steps need the `path` argument. Nested steps get counts and fields
  only: the preview rows are always the selected top-level step's.
- **Edits that add an input AND change a step must use functional
  `setDraft`**: picking a dataset on a nested join calls `ensureInput` (adds
  the input) and then the step `onChange`; with closure state the second
  write drops the first. `prunedInputs` walks sub-pipelines and the SQL
  `in_<alias>` reads, or Save would delete a nested join's input.
- **Spread proposals come from `distinctFieldValuesQueryOptions`** (a
  2000-row PostgREST sample of `data->>field` on the right dataset), because
  a spread with zero columns fails validation and so can never reach the
  diagnostics' `undeclaredCategories`. Diagnostics still drive the "no column"
  warning for categories the sample missed.
- **CodeMirror for expressions and SQL is `@caden/ui/components/code-editor`**
  (lazy + `useIsClient`, same SSR rule as the JSON editor). It does not run in
  jsdom: component tests mock the module with a textarea that exposes the
  `diagnostics` and `completions` props as data attributes. The pure logic
  lives in `lib/expression-assist.ts` (check, completions, SQL names).
- **base-ui Select options do not fire in jsdom via `fireEvent.click`**; test
  select-driven transitions through pure model helpers (`measureWithFn`,
  `repointRight`) and render pre-set steps for the form tests. The
  `DropdownMenu` items DO work (`findByRole("menuitem")`).
- Unknown-typed input fields mean the Calculate form's "Result type" is often
  "depends on the data"; the input metadata (`view_input_meta`) carries names
  only. Output-field labels are still model-only (the Output card has no label
  inputs yet).

## #307 reuse: Duplicate, remap, chaining, Extract to view

- **Pure logic is `data-core/src/views/reuse.ts`** (`remapInputs`, `remapReport`,
  `planExtract`/`applyExtract`, `pruneInputs`); the app wires it
  (`features/views/lib/reuse-actions.ts`, `duplicate-view-dialog.tsx`,
  `extract-view-dialog.tsx`). Extract is tested by running BOTH definitions
  on PGlite (`reuse.pglite.test.ts`): the new view is "run" by saving its
  compiled rows as entries of a new dataset id.
- **A view's field list (`datasets.properties`) only exists after its first
  run** (`view_apply_run` writes it from the row keys). So a freshly created
  view as an input has `fields: []`; the editor/save/runner metas now leave
  `fields` UNKNOWN when the list is empty (otherwise every key picker and the
  validator reject the join). Extract therefore runs the new view BEFORE
  saving the edited one and refuses to rewrite the original when that first
  run fails (the new view stays, with a message).
- **A join's default prefix is a slug of the right input's TITLE**, so
  swapping the right input (remap) or replacing it with the extracted view
  would silently rename copied columns (`deployments.name`). `remapInputs` and
  `planExtract` write the old default prefix down explicitly (only for
  first/last/error/text/list; summarize/spread never use it).
- **Extract output = `fields: []` (every field as named), `emptyFields: keep`.**
  The join then reads the SAVED rows of the new view, not live steps: refresh
  the new view when its inputs change. `first`/`last` without `orderBy` fall
  back to `row_id`, which is new for a view's rows, so such a join can pick a
  different row after Extract (add an `orderBy` to make it stable).
- **Duplicate** copies definition + output labels, drops pinned versions of
  remapped inputs, never copies export profiles and creates with
  `refresh_mode = manual` (auto/live are server-gated).
- **Cycle errors** from `save_view` ("saving this view would create a cycle")
  are rewritten by `explainCycle` using the view summaries' inputs ("X already
  reads this view").
- Tests that mock `@/lib/store/datasets` and render the page must also mock
  `../lib/create-view` (it pulls the projects store, which reads
  `CATALOG_READ_LIMIT` from the mocked module) and add
  `listViewSummariesQueryOptions` to the `view-reads` mock.
