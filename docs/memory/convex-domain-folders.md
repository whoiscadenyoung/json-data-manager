Step B3 moved 23 host modules (+17 tests) into `app/convex/{cms,sources,versions,publishing}/`
(`sources.ts` became `sources/registry.ts`), split 15 host tables out of
`schema.ts` into per-domain `tables.ts`, and pulled the pure chain cores out
of `versions/consumption.ts` into `versions/chain.ts`.

- **Function paths are data, not just code.** The TanStack Query persister
  allowlists namespaces by function name (`light-namespaces.ts`) and stores
  query hashes like `convexQuery|schemas:list|…` in **IndexedDB**. After a
  move, a restored cache would re-subscribe to functions that no longer exist,
  so B3 renamed the namespaces to `cms/*` and bumped `PERSIST_KEY` to
  `light-query-cache-v2`. Any future module move must do the same.
- **Verification that worked without a deployment:** dump
  `schema.export()` before/after (byte-identical, 36 tables) and list every
  registered function `module:name kind visibility` before/after through the
  old→new map (201 identical); bundle every convex module with esbuild (the
  Convex CLI's bundler) to prove the TS-source workspace packages resolve.
- `_generated/api.d.ts` was regenerated by a script that rebuilds only the
  module import list and `fullApi` entries from the files on disk (verified
  first to reproduce the existing file byte-for-byte). Still worth a real
  `convex codegen` before merging.
- **Pitfall:** `git mv` stages the rename with the ORIGINAL content; edits
  made afterwards are unstaged. `git checkout -- <moved file>` then silently
  reverts those edits, and `git stash push -- <paths>` on staged renames
  deletes the files from the tree. Copy files aside instead of using
  checkout/stash on freshly moved files.
- convex-test files moved into subfolders use `import.meta.glob("/convex/**/*.ts")`.
